## 1. Кириллица и ввод

### 1.1. Вторая вкладка не получает фокус программно — подтверждаю

Проверил headless по сценарию отчёта:

```
page = StubPage(); app = TermoClubApp(page); app.start()
item = app.manager.open("terminal", page)
await asyncio.sleep(0.2)
→ input_ready=True, input_focused=False
```

Механика именно та, что описана: `WorkspaceManager.open()` → `activate()` →
`on_focus()` → `focus_input()`, а на этот момент `TerminalView._input` ещё не
создан (`get_content()` вызывается позже, из `_refresh_workspace`), поэтому
ранний выход на `TerminalSession.py:434` (`if not self._view.input_ready`) срабатывает
и фокус не запрашивается. Ничего не перезапрашивает его и после монтирования.

**Исправимо, дёшево.** Три варианта, рекомендую третий:

1. явный `focus_input()` после `stage.show(...)` в `main._refresh_workspace`;
2. отложенный `focus_input()`: задача, которая дожидается `input_ready`;
3. «дожать» в самом вью — `TerminalView.control` при сборке дёргает
   `on_focus_request()`. Тогда фокус не зависит от того, кто и когда смонтировал
   контрол, и падение в `input_ready=False` перестаёт быть проблемой по построению.

Тест: открыть вторую вкладку и проверить, что `focus_input` был запланирован
(в stub-странице — что `run_task` получил вызов `focus`).

### 1.2. Кириллица живёт только при фокусе поля — подтверждаю, исправимо частично

Это не дефект реализации, а свойство платформы: `page.on_keyboard_event` отдаёт
`LogicalKeyboardKey.keyLabel` и текста не содержит, поэтому единственный канал
настоящих символов — IME-поле. Полностью убрать зависимость нельзя.

Что можно сильно улучшить (и стоит): рефокусить поле не только по клику и не
только «после первой латинской буквы», как сейчас в `handle_key`, а на всех
событиях, после которых фокус теряется:

* активация вкладки (`activate`) и монтирование контрола — см. 1.1;
* возврат на маршрут Home из Logs (`route_to_workspace`);
* любая клавиша, поглощённая диспетчером;
* `Tab` — уже сделано.

Гарантию «кириллица всегда работает» без таймера-сторожа дать нельзя; сторож
(раз в 500 мс проверять `input_focused` активной вкладки и просить фокус) —
работает, но выглядит как лечение симптома. Решение по продукту.

### 1.3. Гонка в `TextInputBridge` — подтверждаю, воспроизвёл как чистую логику

```
bridge.feed("a")  -> b'a'
bridge.reset()    # то, что делает clear_input()
bridge.feed("ab") -> b'ab'   # «a» уехала второй раз
```

Отсутствующий RTT-кадр: клиент сформировал «ab» до того, как получил очистку.
**Исправимо, ~10 строк.**

Ключ: текущий `mirror` сбрасывается в `""` и моделирует **новое** состояние поля,
а пришедшее событие относится к **старому** состоянию. Различить их можно по
монотонности: значение, которое является расширением уже отправленного, — это
устаревший снимок, и слать надо только хвост.

```python
def feed(self, value: str) -> bytes:
    previous, self._mirror = self._mirror, value
    if value == previous:
        return b""
    if previous and self._cleared and value.startswith(previous):
        # Устаревший снимок: клиент ещё не применил очистку.
        return value[len(previous):].encode("utf-8")
    ...  # как сейчас: префикс / замену считаем от пустого поля
```

где `_cleared` — «после последнего `feed` поле просили очистить». Пост-очистный
ввод (`"a"` → очистка → `"b"`) расширением не является, идёт по старой ветке и
работает как раньше.

Честное ограничение: это эвристика. Полностью детерминированное решение — не
очищать поле и считать diff по всему значению, как в `xterm.dart`, но тогда
поле начинает обрабатывать `Backspace`/`Delete` само, а `Delete` в терминале —
это `ESC[3~`, не `\x7f`. Разводить их придётся через перехват в диспетчере.
Считаю это избыточным: выигрыш только в экзотическом случае «выделить и заменить»
внутри невидимого поля 1×1 px.

### 1.4. Пробелы в раскладке — подтверждаю, исправимо

* `bytes([ord(key.lower()) - 96])` (`TerminalKeymap.py:84`): при нелатинском
  `keyLabel` даст `ValueError` (>255). Гипотетический путь, но проверка стоит
  одной строки: `if not key.isascii(): return None` (или clamp по диапазону).
* Не обрабатываются `Ctrl+Space` → `\x00`, `Ctrl+[` → `\x1b`, `Ctrl+2`/`Ctrl+6`,
  `Ctrl+Backspace` → `\x17`, `Alt+<символ>`. Добавляется таблицей в `SPECIALS` +
  веткой на `ctrl`; тесты — по образцу существующих в `TerminalKeymap_test.py`.

Оговорка: `Ctrl+<буква>` приходит из `KeyboardEvent` лейблом в верхнем регистре —
для нелатинской раскладки это по-прежнему US-логика. Такова цена схемы; на
комбинации это влияет заметно меньше, чем на текст.

## 2. Отображение и ресайз

### 2.1. Размер только по `Container.on_size_change` — подтверждаю

Скрытые вкладки (`visible=False`) событий о размере не шлют, фолбэка нет.
**Исправимо, но требует проверки в живом окне.**

Правка в отчёте названа неточно: во Flet атрибут — `page.on_resize`
(`PageResizeEvent` с полями `width`/`height`), а не `page.on_resized`. Проверено в
исходниках 0.86.5 и 1.0.0 — есть в обеих версиях.

Практический план:

1. `ApplicationLayout` знает всю геометрию (левая/правая панели, по 16 px на
   тумблеры, `top_height=40`, `bottom_height=28`), поэтому из размера страницы
   вычисляется размер рабочей области детерминированно;
2. `TerminalSession.resize_from_page(w, h)` считает колонки/строки той же
   арифметикой, что `TerminalView._on_size_change` (формулу вынести в общую
   функцию, чтобы не было двух источников правды);
3. вызывать это: на `page.on_resize`, и при `WorkspaceStage.show()` для той
   вкладки, которая стала видимой.

Так снимается и «пересчёт при показе вкладки зависит от того, пришлёт ли клиент
событие», и потеря размера при переключении Home/Logs.

### 2.2. Артефакт при сжатии окна — подтверждаю по коду

`TerminalSession.resize()` применяет **только первое** событие серии
(`if self._resize_task is not None: return`), дальше ждёт «тишины» до 0.3 с.
Значит во время перетаскивания сетка остаётся размера первого события, а
контейнер уже сжался: лишние колонки и строки обрезаются `HARD_EDGE` — визуально
«терминал поехал, приглашение и курсор пропали». При росте окна — зеркально,
полоса пустоты справа/снизу.

**Исправимо, ~15 строк.** Причина — в том, что одним дебаунсом закрыты две разные
операции: визуальная (пере-разметка сетки) и дорогая (TIOCSWINSZ + SIGWINCH).
Разделяем:

* размер **экрана** применять на каждом событии (он обязан совпадать с
  контейнером) и перерисовывать через обычный `_refresh()` — троттлинг 20 Гц уже
  ограничивает стоимость; `_refresh(force=True)` тут не нужен;
* **PTY** ресайзить по-прежнему одним применением по «тишине» — SIGWINCH-шторм
  остаётся предотвращённым, тест на «20 событий → 2 `bridge.resize`» продолжает
  проходить.

Альтернатива (проще, чуть хуже): применять сразу при уменьшении и дебаунсить
только рост.

### 2.3. Метрики шрифта — замечание по адресу, но обоснование в отчёте неверно

Проверил по `cmap` самого бандла `assets/fonts/jb-mono-regular.ttf`:

```
Cyrillic А-я:              missing 0/64
box drawing 2500–257F:     missing 0/128
block elements 2580–259F:  missing 0/32
arrows 2190–21FF:          missing 0/112
powerline E0B0:            missing 0/1
emoji 1F600:               missing 1/1
```

То есть сценарий «JetBrains Mono не даст кириллических глифов → включится fallback
с другой шириной знакоместа» **не наступает**: кириллица, рамки, блоки и стрелки в
шрифте есть. Реальные риски остаются два, и они уже, чем в отчёте:

* эмодзи и CJK — глифов нет, Flutter подставит другой шрифт с другой шириной
  (`ls` в каталоге с эмодзи, `cat` чужого файла) → сетка поедет;
* DPI-масштабирование: `MONO_ASPECT`/`MONO_LINE_HEIGHT` — доли виртуального
  пикселя, при масштабировании округление накапливается на 40+ строках.

**Исправимо частично.** Что можно сделать:

* сразу и дёшево: считать колонки с запасом (округление вниз уже есть, добавить
  отступление на одну колонку) и, главное, сохранять инвариант «сетка никогда
  больше контейнера» — тогда любая ошибка метрики приводит к пустому полю справа,
  а не к обрезанному приглашению;
* надёжно, но дороже: мерить реальную ширину знакоместа скрытым
  `ft.Container(on_size_change=...)` с `ft.Text("0" * N)` — один замер на старте,
  `char_width = width / N`, `line_height = height`. Требует проверки в живом окне
  (нужно убедиться, что Flet отдаёт intrinsic-размер, а не ширину контейнера).

Предлагаю сделать первое сейчас, второе — отдельной задачей, если DPI-эффект
подтвердится на практике.

### 2.4. Несогласованность `StackFit` — не дефект

Снаружи `EXPAND`, внутри `LOOSE` — это не небрежность, а необходимость: внешний
фит обязан растянуть рабочую область, внутренний — дать блокам `Text`/`TextField`
измериться по себе. Переключение внутреннего на `EXPAND` растянет бокс спанов на
ширину контейнера, но раскладку глифов не изменит — эффект косметический, риск
нулевой, польза нулевая. Предлагаю не трогать, а дописать причину в docstring
(там уже есть абзац о внешнем `StackFit`).

## 3. Общий анализ

### 3.1. `SmartCLIPtyBridge.pump` вешает event loop — ПОДТВЕРЖДАЮ, это блокер

Воспроизвёл (продюсер `/usr/bin/yes`, сторожевой поток):

```
$ yes-продюсер + ticker(6 × 50 мс) в одном loop
WATCHDOG: 3s passed with no ticks -> event loop starved by pump()
```

В `pump()` ветка «данные есть» делает `on_data(chunk); continue` без `await`, а
`PtySession.pump()` — неблокирующее чтение, которое при непрерывном выводе
всегда возвращает данные. Цикл не отдаёт управление: замирают и отрисовка, и
ввод, и закрытие вкладки. Замечание отчёта верное на 100%.

**Исправимо одной строкой, и я проверил, что исправление работает:**

```python
if chunk:
    on_data(chunk)
    await asyncio.sleep(0)   # отдать управление loop'у
    continue
```

Прогон с этой правкой: `FIX OK: loop stayed responsive with a flooding producer`.
`asyncio.sleep(0)` не добавляет задержки, когда данных нет (там уже
`POLL_INTERVAL`), а пропускная способность остаётся ограничена размером буфера
чтения. Раз в N итераций или по времени — не нужно.

## 4. Что исправить нельзя или не нужно

* **Полная независимость кириллицы от фокуса IME-поля (1.2).** Платформа не даёт
  текста в `KeyboardEvent`; единственный символьный канал — поле ввода. Любое
  решение — это «держать фокус агрессивнее» либо таймер-сторож, а не устранение
  причины. Стоит зафиксировать в `__doc/workspace-tabs.md` как осознанное
  ограничение (там уже есть близкая запись).
* **«Сетка всегда идеально совпадает с контейнером при любой метрике шрифта»
  (2.3).** Пока ширина знакоместа не измерена, это оценка; измерение требует
  живого окна и даёт свой источник истины. Разумный уровень — инвариант «сетка не
  больше контейнера» + запас в одну колонку.
* **Дебаунс как таковой (2.2).** Убирать его целиком нельзя: без него один
  toggle панели даёт ~18 SIGWINCH и столько же полных перерисовок — это
  регрессия того, что уже починено. Исправлять нужно разделение слоёв, а не
  отказ от склейки.
* **Визуальная приёмка.** Цвет, курсор, реальный ресайз, поведение скроллбара,
  кириллица в живом окне — проверить из песочницы нечем. Все правки по 2.1–2.3
  требуют прогона в GUI до того, как их можно считать сделанными.

## 5. Ответы на вопросы из раздела 4 отчёта

1. **Фокус.** «Всегда держать фокус в скрытом поле активной вкладки», но
   событийно: монтирование контрола, активация вкладки, смена маршрута, любая
   поглощённая клавиша, клик. Таймер-сторож — только если практика покажет
   дыры; начинать с событий.
2. **Гонка `TextInputBridge`.** Вариант (a) в моей редакции: помнить
   последнее отправленное значение и трактовать расширение-догоняющий снимок как
   хвост. Поле по-прежнему очищаем. Вариант (b) (не очищать и считать diff
   целиком) отвергаю из-за `Delete` и `Backspace`, которые поле начнёт
   обрабатывать само.
3. **Ресайз.** Да, опираться на `page.on_resize` (не `on_resized`) плюс
   детерминированная геометрия из `ApplicationLayout`; метрики шрифта — во вторую
   очередь. Неактивные вкладки достаточно пересчитывать при показе: заранее
   ресайзить скрытые вкладки бессмысленно, их размер всё равно изменится к моменту
   показа.
4. **Приоритеты.** 3.1 (блокер, одна строка) → 1.1/1.2 (кириллица, это боль
   пользователя) → 2.2/2.1 (артефакты ресайза) → 1.3/1.4 → гигиена из 3.2.
5. **Публичные методы.** `focus_input`, `TextInputBridge`, `WorkspaceStage` —
   внутренние для репозитория, внешних потребителей нет (проверил по импортам).
   Менять можно свободно, обновляя тесты.
6. **Тест приглашения.** Не завязываться на `PS1`: писать в PTY маркер и ждать
   его в отрисованном экране. Вариант с `PS1` через `env` тоже подтверждён, но
   требует `--norc` и проброса `env` в мост — лишняя связность теста с шеллом.

## 6. Предлагаемый порядок работ

1. **Блокер.** `await asyncio.sleep(0)` в `SmartCLIPtyBridge.pump` + тест на
   «продюсер + тикающая задача в одном loop». *(правка проверена, ~5 строк)*
2. **Кириллица.** Фокус после монтирования/активации (1.1), рефокус при смене
   маршрута и после поглощённых клавиш (1.2), хвостовая логика в
   `TextInputBridge` (1.3), безопасность `TerminalKeymap` и новые комбинации (1.4).
3. **Ресайз.** Разделить визуальный и PTY-ресайз (2.2), добавить
   `page.on_resize` + геометрию и пересчёт при показе вкладки (2.1), запас по
   колонкам (2.3, первая часть). Всё — с прогоном в живом окне.
4. **Гигиена.** `Callable`, шим под 1.0/`InputBorder`, пины и
   `requirements-dev.txt`, идемпотентный `setup_logging`, grace в `_kill_child`,
   отложенный `on_terminated`, детерминированный тест приглашения.
5. **Решения по продукту.** Что показывать в правой панели вместо
   ghostty/kitty; drag-resize панелей или удаление мёртвых полей.

Пункты 1–2 не требуют GUI и могут быть сделаны и проверены тестами сразу;
пункт 3 сделан, но не проверен, пока не появится живое окно.
