## 1. Передача кириллицы с клавиатуры в оба встроенных терминала

Архитектура ввода выбрана верно: служебные клавиши и `Ctrl+<буква>` идут через `page.on_keyboard_event` в `TerminalSession.handle_key`, а настоящие символы (кириллица, регистр, вставка) — через скрытое IME-поле `ft.TextField` в `TerminalView`, с дедупликацией по `input_focused`. Оба терминала (`terminal` и `terminal-gpu`) используют общую логику, поэтому дефекты у них общие.

### 1.1. При открытии вторая вкладка не получает фокус программно

`WorkspaceManager.open()` (`termoclub/app/workspace/WorkspaceManager.py:57`) вызывает `item.start(page)` -> `activate()` -> `on_focus()` -> `TerminalSession.focus_input()`, но в `focus_input()` (`termoclub/core/sessions/terminal/TerminalSession.py:434`) стоит ранний выход `if not self._view.input_ready ... return`. На этот момент скрытое поле ещё не создано: `get_content()` строится позже, в `_refresh_workspace` через `_notify()` (`termoclub/main.py:108`).

Проверено: после `open()` не планируется ни одной focus-задачи. Дальше всё держится на `autofocus=True` у поля. По документации Flet «если autofocus установлен у нескольких контролов, фокус получает первый добавленный», а скрытые контролы (`Control.visible = False`) фокус держать не могут. Итог: после открытия второго терминала активное поле без фокуса, `_input_focused()` возвращает False, и печатный ввод уходит в fallback-диспетчер с US-логикой (латиница). Кириллица начинает работать только после клика или после первого набранного символа.

Предложения:

- после `stage.mount(...)` в `_refresh_workspace` явно вызывать `focus_input()` у активной сессии;
- либо сделать `focus_input()` отложенным (задача, которая дождётся `input_ready`);
- либо вовсе не полагаться на `autofocus`.

### 1.2. Кириллица полностью зависит от фокуса поля

Любая потеря фокуса (клик по другому контролу, Tab, переход на маршрут Home/Logs и обратно, `page.push_route`) роняет кириллицу в латинский fallback, пока пользователь снова не кликнет по терминалу. Стоит обсудить событийный или периодический авто-рефокус активной вкладки.

### 1.3. Гонка в TextInputBridge (возможные дубли символов)

`TerminalView._on_field_change` на каждый символ вызывает `feed()` и сразу `clear_input()`, а `feed()` (`termoclub/core/sessions/terminal/TextInputBridge.py:32`) сбрасывает `mirror=""`. Если клиент не успел применить очистку до следующего нажатия (медленный RTT, быстрый набор), следующий `on_change` принесёт накопленное значение, diff посчитается от пустой строки, и уже отправленный префикс уйдёт повторно. Локально обычно незаметно, но на вебе или слабом устройстве дубли вероятны.

### 1.4. Пробелы в раскладке

- `TerminalKeymap.to_bytes` (`termoclub/core/sessions/terminal/TerminalKeymap.py:82-85`) с `bytes([ord(key.lower()) - 96])` безопасен только пока `keyLabel` — латиница США; нелатинский лейбл даст `ValueError` (значение больше 255). Нужна проверка диапазона/`isascii()`.
- Не обрабатываются `Ctrl+Space` (NUL), `Ctrl+[` (ESC), `Ctrl+2/6`, `Ctrl+Backspace`, `Alt+<не-буква>`.

## 2. Отображение терминалов во вкладке при изменении/масштабировании окна

### 2.1. Пересчёт сетки только по Container.on_size_change

`TerminalView._on_size_change` (`termoclub/core/sessions/terminal/TerminalView.py:312`) — единственный источник нового размера. Скрытые вкладки, по документации Flet, событий не эмитят; пересчёт при показе вкладки зависит от того, пришлёт ли клиент событие после того, как размер менялся «за кадром». Фолбэка на ресайз страницы нет.

Предложение: слушать `page.on_resized` и явно пересчитывать размер активной вкладки в `WorkspaceStage.show()`.

### 2.2. Артефакт при сжатии окна

Размер применяется с дебаунсом 0.12–0.3 с (`RESIZE_DEBOUNCE` / `RESIZE_MAX_WAIT`). Первый размер применяется сразу, дальше — хвостовой задачей. Между этими моментами сетка больше контейнера, и `HARD_EDGE` обрезает низ — как раз приглашение и курсор. Внешне это выглядит как «терминал поехал/пропал» при ресайзе.

### 2.3. Жёстко зашитые метрики шрифта

`MONO_ASPECT = 0.6`, `MONO_LINE_HEIGHT = 1.25`. При DPI-масштабировании или подмене шрифта (если JetBrains Mono не даст кириллических глифов, включится fallback с другой шириной знакоместа) сетка разъезжается: либо обрезка правых колонок, либо переполнение по строкам. Надёжнее измерять реальную ширину знакоместа (например, эталонным скрытым `ft.Text`) или брать колонки с запасом.

### 2.4. Несогласованность фитов

Снаружи `WorkspaceStage` использует `StackFit.EXPAND`, внутри `TerminalView` — `StackFit.LOOSE`. LOOSE позволяет `Text` влиять на intrinsic-размер; для сетки фиксированного размера логичнее унифицировать.

## 3. Общий анализ кода

### 3.1. [Высокий] SmartCLIPtyBridge.pump не отдаёт управление event loop

`termoclub/core/sessions/terminal/SmartCLIPtyBridge.py:140` — при наличии данных идёт `on_data(chunk); continue` без `await`. При непрерывном выводе (например, `yes`) цикл крутится синхронно и вешает весь UI. Воспроизведено: после старта `await asyncio.sleep(2.0)` в том же loop не просыпается. Лечится `await asyncio.sleep(0)` в ветке с данными (или `await` раз в N итераций / по времени).

### 3.2. Прочее

- `SessionFactory`: аннотации `dict[str, callable]` (`termoclub/core/sessions/SessionFactory.py:41`), `list[callable]` в `core/events.py` — нужен `Callable`.
- `ft.InputBorder.NONE` устарел в Flet 1.0 (warning в тестах) -> `ft.NoInputBorder()`.
- `requirements.txt`: нет pytest/pytest-asyncio; `flet>=0.86` без верхней границы, хотя код рассчитан на API 1.0.
- `logging_setup.setup_logging()` не идемпотентен — повторный вызов продублирует хендлеры.
- `PtyBridge._kill_child` шлёт SIGHUP и сразу SIGKILL, `waitpid(WNOHANG)` может не собрать ребёнка (зомби), нет grace-периода.
- `WorkspaceManager.close()` вызывается из `on_terminated` внутри той же pump-задачи и отменяет её же — работает, но хрупко.
- Переход Home/Logs размонтирует `_workspace_root`, теряя фокус и, возможно, размеры терминалов (тот же класс проблемы, что в 1.2 и 2.1).
- `core/config.py` (`ghostty`/`kitty`) не связан с встроенными терминалами — терминологическая путаница в UI и README.
- `CollapsiblePanel` объявляет `min_width`/`max_width`, но drag-resize нет; при toggle ширина возвращается к `default_width`.

## 4. Вопросы к обсуждению

1. Фокус для кириллицы: делаем «всегда держать фокус в скрытом поле активной вкладки» с авто-рефокусом по событиям/таймеру или оставляем только фокус по клику?
2. Гонка `TextInputBridge`: (a) не сбрасывать `mirror`, а гасить эхо через generation/ожидаемое значение; (b) не очищать поле и считать diff целиком (тогда надо разводить Backspace с диспетчером); (c) очищать поле только по подтверждению от клиента?
3. Ресайз: можно опираться на `page.on_resized` и измерение метрик шрифта или нужен вариант без измерений (эмпирическая калибровка колонок)? Нужно ли ресайзить неактивные вкладки заранее или достаточно пересчёта при показе?
4. Приоритеты: сначала фокус/кириллица, потом ресайз, или наоборот? Подвисание `SmartCLIPtyBridge` стоит чинить первым — это блокер.
5. Есть ли ограничения на изменение публичных методов (`focus_input`, `TextInputBridge`, `WorkspaceStage`) или можно править свободно с обновлением тестов?
6. Тест про приглашение (`#`/`$`) — переписать на нейтральный маркер готовности шелла (или запускать с фиксированным `PS1`)?
